## 実装の要点

- `FlowBake.compeito`: BFS親ポインタ（リーフインデックス型、.bチャネル）をボクセルインデックス型の方向フィールド（`texel=(x+z*GSX, y)`、xyz=方向・w=有効）に1パスで変換。シムは敵ごとに**テクスチャ1フェッチ**（5タップXZ平均で平滑化）。
- `FlowFieldBridge`: 静的テクスチャ（voxelToLeaf / leafVoxelIndex）を一度だけアップロード。フロー更新は1秒間隔 or ソース移動>1.5m時。ソース=「群衆重心に最も近いプレイヤー」（ミラーから算定、各クライアントローカル）。
- 壁ずり: 移動先＋半径0.35mのプローブが壁ボクセルならX/Z軸スライドにフォールバック、完全閉塞なら停止。
- フォークの`RequestFlowField`はflood完了まで最大`gsX+gsY+gsZ`=134反復（itersPerFrame=16で約9フレーム）。

## 検証上の注意

- pos/stateミラーは非同期readbackのチェーンで取得するため、**監査の瞬間によってはスポーン直後スロットのposが初期値のまま**（stateは新鮮）になり得る → 監査は数秒置いてから実施する（一過性アーティファクト、シムのバグではない）。
- PlayMode中のプロキシ経由フィールド読み取りはstale値を返す → 監査スニペットは`GetProgramVariable`経由でヒープを読むこと。

## スタック敵の完全解決（2026-10-31追加検証）

初回検証後に「収束後も敵が壁端・扉に残留する」問題を発見し、4段階の修正で **stuck=137 → 0** を達成:

1. **グリッド高さ6→2ボクセル**: 壁3mに対しグリッドが6ボクセル分の高さがあると、BFSが建物の**上空(y=3..5)を迂回ルートとして選択**し、地面クランプされた敵が従えない「上へ行け」フローを生成して壁にピンning。地上層のみの2ボクセルグリッドで封鎖（グリッドも8192ボクセルに縮小＝高速化）。
2. **ボクセル化プローブ縮小(0.5→0.45)**: フォークに`voxelProbeShrink`公開フィールド追加。OverlapBoxの**接触判定**で壁面に正接する歩行可能ボクセルまで「壁」化していた問題（境界ピンningの根本原因）を解消。
3. **分離力キャップ(max 1.4 < 移動速度3.2)**: 密集圧力が移動意識を上回り扉を栓状に塞ぐ問題を防止。
4. **ジャム脱出ナッジ**: ステップが完全クランプされた（密集圧力で壁に押し付けられた）際、**両タンジェント方向を本体半径込みでプローブ**し実際に抜けられる方向へスライド（スロット偶奇でタイブレーク）。

最終状態: **alive=500 / stuck=0 / centroid=(−0.1, 0.0)**（プレイヤー位置に全収束、残留ゼロ）。
